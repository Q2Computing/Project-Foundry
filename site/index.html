Q2 Computing / Project Foundry / Arbitrum Stylus

Beat a foundry cell. Prove it in public. Settle it on Stylus

Standard-cell design is a private consultancy. The knowledge of how to trade threshold voltage, gate area, and leakage for speed sits inside a few foundries and costly tool vendors. Project Foundry turns it into a public commodity: on the open sky130 PDK an agent finds a fabricable improvement the foundry left on the table, an independent oracle re-measures the claim from scratch, and the verified win is anchored on Arbitrum Stylus. The method stays open and contributable while each improvement still earns, so anyone can run the oracle, check the result, and compete. The same discipline carries to the open 3nm process, where the wins are worth real money, opening a class of American, foundry-grade design assets that institutional and retail capital can underwrite

Measurement and CI run today. The Stylus settlement is written and prepared, not yet deployed

The move inside the energy band

The whole sky130 high-density buffer ladder is one recipe: standard-Vt nfet and high-Vt pfet, in every cell (confirmed from the PDK netlist), tuned for low leakage. That leaves rise-edge speed on the table at every drive strength. A real 32 or 64-bit datapath lives inside the ladder's energy-per-cycle band, it does not pay for over-driven cells outside it. So the honest question is whether, inside that band and at the same finger count, a fabricable combination of the PDK's own threshold-voltage masks can beat the ladder. It can. Swapping the high-Vt pfet for the standard one, and optionally the nfet to low-Vt (real masks, mixable finger by finger, no new implant), moves the same cell left: 22% lower EDP than buf_16 at the same size and slightly less dynamic energy. The cost is leakage, which is exactly what the foundry bought with high-Vt, so this is a hot-path move: worth it where the cell switches enough to amortize it, wrong where it idles. Choosing it per context is the differentiation, and one fixed library cannot make that choice

Every point is measured on one ngspice bench, reproducible with analysis/linearcomb.py and leak_inband.py. Settlement on Arbitrum Stylus

The point of a win is not a screenshot, it is a durable, verifiable record. Each verified improvement is committed as a hash for a Stylus contract on Arbitrum to record. Anyone holding the netlist can recompute the hash and check it; no one else can read the design

record(bytes32 artifact_hash, uint16 label, uint16 context)
// best win: EDP +14.8% vs buf_16
record(0xbbe5a7f1...f8f7c, 1482, 16)
//         hash of the design bundle   basis points   drive strength

label is basis points of EDP improvement, context is the part's drive strength. The hash is the artifact; the netlist never has to be published. The contract is written in Rust for Arbitrum Stylus and passes cargo stylus check. Status: not deployed. anchor.py prepares this record() call, it does not submit it (that needs a funded key)

Why it holds up

Same transistors

Candidates use only the nfet_01v8 and pfet_01v8_hvt units the foundry buffers are built from. A win is a better arrangement, not a faster device

Independent judge

The generator never grades its own work. A clean CI runner fetches the pinned PDK and reproduces every number bit for bit

Disclosure safe

Only a hash and a coarse label reach the chain. Anyone with the netlist can verify, no one else can read it

Scope, stated plainly: these are deck-clean, SPICE-characterized results on the open PDK, not foundry-qualified cells. Area is a transistor-width proxy, not laid-out area. Layout, DRC and LVS are the next step
